# 需求分析与用户研究 Demo

## 目标用户

本产品面向关注预测市场的研究型用户，包括加密交易者、事件交易研究员、宏观/体育/政治事件观察者，以及希望把 AI 用在投资研究流程中的个人开发者。

## 用户痛点

1. 市场价格是概率，但用户很难快速判断价格和自己判断之间的差距是否足够大。
2. Polymarket 市场数量多，单个市场的流动性、价差和结束时间差异明显，人工扫描效率低。
3. 只看“赔率便宜”容易忽略仓位控制，真实亏损通常来自过度下注、相关市场重复暴露和流动性不足。
4. 聪明钱钱包活动有参考价值，但如果不和市场上下文结合，容易变成噪声。
5. 移动端演示和轻量使用很重要，尤其是在面试、路演或日常观察场景中。

## MVP 假设

- 用户愿意先手动输入或接受模型估计的 fair probability。
- 只要能够展示 EV Gap、风险标签和仓位建议，MVP 就有足够演示价值。
- 自动交易不是第一阶段刚需；先做分析和风控，可以降低资金风险。
- PWA 能覆盖 iPhone 演示需求，比在 Windows 上强行构建 iOS App 更现实。

## 核心用户流程

1. 用户打开首页，看见热门市场和 Top Opportunities。
2. 用户进入 Analysis，查看每个机会的 EV Gap、fair probability、价格和建议仓位。
3. 用户点开详情，手动调整 fair probability，观察 EV 和仓位是否仍然成立。
4. 用户进入 Smart Money，查看 mock 钱包的大额交易和近期动作。
5. 用户进入 Settings，调整资金规模、EV 阈值、Kelly fraction、单市场上限和语言。
6. 当 EV Gap 超过阈值时，通知服务占位可以触发提醒逻辑。

## 产品取舍

MVP 暂不实现真实下单。原因是预测市场交易涉及私钥、签名、订单状态、滑点、流动性和合规风险。把交易执行留在后端和人工确认之后，是更稳妥的产品路线。

MVP 暂不直连 OpenAI API 做实时报价解释。前端直连会暴露 API Key，也不利于缓存、成本控制和审计。正式版本应由后端统一代理 AI 请求。

## 成功指标

- 用户能在 30 秒内理解当前最值得关注的市场机会。
- 用户能看懂机会来自 price 与 fair probability 的差距，而不是单纯“AI 推荐”。
- 用户能看到建议仓位被风险参数约束，而不是无限放大 Kelly。
- 面试官可以从 README、截图、体验包和代码结构理解完整交付链路。

## 后续访谈问题

- 你在判断 Polymarket 市场时，最依赖哪些外部信息源？
- 你能接受 fair probability 由 AI 估计，还是更希望自己输入？
- 你更关注高 EV 小流动性机会，还是低 EV 高流动性机会？
- 仓位建议应该更保守，还是允许用户选择激进模式？
- 聪明钱模块中你更想看钱包胜率、资金规模、持仓变化还是市场聚类？
